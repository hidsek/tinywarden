# tinywarden

[English](README.md) | 日本語

**集めるから、狙われる。**

クラウドが破られたら、あなたの保管庫も一緒に持っていかれる。だから、手元に置く。tinywardenの保管庫は、USBで挿した小さなデバイスの中。ネットからは届かず、新しい端末でログインするには、デバイスのボタンを押します。手元に置くだけなので、パスワードマネージャーをパスキーで守る必要もありません。公式のBitwardenアプリで使えて、サイトのパスキーも保存できます。

ローカルにすれば何でも守れる、というわけではありません。ログインした端末がマルウェアに入られたら守れませんし、デバイスを盗まれれば、中の暗号文を手元で総当たりされます。守りの土台は、強いマスターパスワード（とArgon2id）と、端末の安全です。

USBで挿したESP32-S3の基板の中で動く、小さな非公式のBitwarden互換サーバです。クラウドも、家のサーバも、ネットワークも使いません。保管庫は基板の中にあり、公式のBitwardenのブラウザ拡張機能とスマホのアプリが、USBのネットワークを通して基板とやり取りします。

> **非公式で、試作の段階です。** tinywardenは趣味で作ったものです。Bitwarden, Inc.とは関係がなく、認められても、サポートされてもいません。第三者による安全性の確認（監査）も受けていません。本物のパスワードを入れる前に、[安全性の考え方](#安全性の考え方)を読んでください。控え（バックアップ）は、必ず別の場所にも置いてください。

**版 0.2.0：手元ではうまく動いているので、公開しました。** 自分の機器（下の一覧）では毎日使っていますが、まだ1人分の環境でしか試していません。ぜひ手元で試して、動いたこと・動かなかったことを教えてください。壊してみるのも、良くしてくれるのも歓迎です。一緒に楽しめたらうれしいです。[CONTRIBUTING.md](CONTRIBUTING.md) も見てください。

## 仕組み

- 基板は、USBのネットワークアダプタ（CDC-NCM）として見えます。基板は `192.168.237.1`、パソコンやスマホはDHCPで `192.168.237.2` になります。ゲートウェイやDNSは渡さないので、パソコンやスマホのインターネットはそのまま使えます。
- 公式アプリが使うBitwardenのAPIのうち、必要な部分だけをHTTPSで提供します。証明書は、初めて起動したときに基板の中で作ります。
- 暗号化は、Bitwardenと同じく公式アプリの中で行います。基板が持つのは暗号文だけです。そのうえで、基板は保存する記録を全部、もう一度暗号化します（AES-256-GCM。鍵はログインしたあとにだけメモリに置きます）。ユーザー名は保存しません。
- アカウントの作成と、マスターパスワードでのログインには、基板のBOOTボタンを押す必要があります（待っているあいだ、基板のLEDが光ります。30秒）。
- 保管庫は、フラッシュの上の小さなログ形式の領域に保存します。任意のバイトで電源が切れる場合を模したテストをしています。

## こだわったところ

セキュリティと使いやすさの両立です。保管庫は手元のハードウェアに1つだけ。それに、持っているどの機器からも、同じやり方でつながります。

- **どの機器でも、同じ保管庫。** Mac、Windows、iPhone、Androidが、同じ基板に、同じサーバーのURLと同じ公式アプリでつながります。挿して、一度ログインすれば使えます。ただ、使い心地はBitwardenのアプリ次第です。どの機器で使えるかも、アプリと、その機器がUSBのネットワークに対応しているかで決まります（[動いたもの](#動いたもの2026-11-19に確認)）。
- **公式のアプリを、そのまま使う。** 改造したアプリや、独自の拡張機能は作っていません。ストアから入れたBitwardenの拡張機能とスマホのアプリで、サーバーのURLを基板に向けるだけです。
- **物理的なひと手間。** アカウントの作成、ログイン、控えの保存、KDFの変更、全部消すときは、基板のBOOTボタンを押すまで進みません。マスターパスワードを10回間違えると、保管庫を消します。
- **基板は、秘密を見ない。** 基板に入るのは暗号文だけです。マスターパスワードも保管庫の鍵も、基板には届きません。管理ページとマージのページの暗号の計算は、ブラウザの中で行います。
- **盗まれても、分かることが少ない。** ユーザー名（メール）を保存しないので、フラッシュを読み出した人は、ユーザー名とマスターパスワードを組で当てるしかありません。ほかは全部暗号化してあり、項目の数・種類・日時も読めません。
- **何の機器か、黙っている。** 管理ページはいつも鍵付きです。鍵を外す前は機器の情報しか出さないので、挿しただけの人には何の機器か分かりません。
- **電源が切れても壊れない。** 保管庫は小さなログ形式の保存領域で、任意のバイトで電源が切れる場合を模したテストをしています。
- **Web保管庫がなくても、Argon2idにできる。** 公式のアプリはアカウントを必ずPBKDF2で作り、変えられるのはBitwardenのWeb保管庫からだけです。Web保管庫は基板に入らないので、管理ページで変えられるようにしました。
- **データに、いつでも手が届く。** 管理ページからの控え、2つの保管庫を比べてふつうのBitwardenのエクスポートを作るマージのページ、どのBitwardenやVaultwardenのアカウントにも戻せる手順を用意しています。アプリの更新でtinywardenが動かなくなっても、閉じ込められません。
- **じゃまをしない。** ゲートウェイやDNSを渡さないので、パソコンのインターネットはそのまま使えます。一度ログインすれば、基板がなくてもアプリは使えます。
- **限界を正直に書く。** 守れないことは、[安全性の考え方](#安全性の考え方)に書いてあります。

## パスキー

Bitwardenはパスキーを保管庫の項目の中に保存します。tinywardenは項目を受け取ったまま保存するので、パスキーも他の項目と同じように同期されます。インポートした保管庫のパスキーでのログインと、新しいパスキーの登録は確かめました。新しく登録したパスキーを、別の機器で同期して使うのは、まだ試していません。

## ハードウェア

USBを直接扱えて、フラッシュ4MBとPSRAM 2MBを積んだESP32-S3の基板。開発には「ESP32-S3 SuperMini」（ESP32-S3FH4R2）を使いました。GPIO48のLEDと、GPIO0のBOOTボタンを使います（開発に使った基板のGPIO48はふつうのLEDで、赤く光ります。GPIO48がWS2812の色つきLEDの基板では、`idf.py menuconfig` の tinywarden > LED on GPIO48 で選べます）。この基板の「BAT」のLEDは充電回路のもので、ファームウェアからは消せません。

## できあがったバイナリを書き込む

**ブラウザから:** https://hidsek.github.io/tinywarden/ （パソコンのChromeかEdge）。基板をダウンロードモードにして、ボタンを押します。「Erase device」にチェックを入れるのは、初めて入れるときだけです。ページは1回きりの**初回コード**を表示し、そのハッシュを基板に書きます。アカウントを作るまで、このコードで管理ページを開けます。書き込む前に控えてください。

**esptoolで:** GitHubのリリースごとに、`tinywarden-<version>-esp32s3.bin`（ブートローダ、パーティションテーブル、アプリを、アドレス `0x0` 用に1つにまとめたもの）と `SHA256SUMS` を置いています。ハッシュを確かめ、基板をダウンロードモードにして（BOOTを押したまま、RSTを押して離し、BOOTを離す）、次を実行します。

```sh
pip install esptool
esptool.py --chip esp32s3 erase_flash                                   # 初めてのときだけ。保管庫も含めて全部消えます
esptool.py --chip esp32s3 write_flash 0x0 tinywarden-<version>-esp32s3.bin
python3 -I tools/setup_code.py setup.bin                                # 初回コードを表示する（なくてもよい。下を参照）
esptool.py --chip esp32s3 write_flash 0x3F0000 setup.bin
```

初回コードは、アカウントを作る前に管理ページを開くためだけのものです。無くても、先にアカウントを作れば、そのアカウントで管理ページを開けます。

RSTを押すと起動します。Espressifのブラウザ用の書き込みツール（https://espressif.github.io/esptool-js/ 、ChromeかEdge）に、同じファイルをアドレス `0x0` で渡す方法もあります。

すでに保管庫が入っている基板を更新するときは、`erase_flash` を飛ばします。イメージを書き込んでも、保管庫と証明書はそのまま残ります。それでも、先に控えを取ってください。**v0.2から上げるとき:** v0.3は保存の形が違い、v0.2の保管庫を開けません。先にエクスポートして、消してから、インポートし直します（[docs/MANUAL.md](docs/MANUAL.md)「v0.2からv0.3に移す」）。

このバイナリは、タグを付けたソースから、`firmware/sdkconfig.defaults` だけで作っています（開発用の設定はオフ）。証明書と鍵は、基板ごとに初めて起動したときに作るので、イメージの中に秘密の情報は入っていません。

## 自分で作って書き込む（ESP-IDF 5.5）

```sh
cd firmware
idf.py set-target esp32s3
idf.py build
```

基板をダウンロードモードにして（BOOTを押したまま、RSTを押して離し、BOOTを離す）、次を実行します。

```sh
./flash.sh          # 作って、書き込んで、アプリを起動する
./flash.sh --wipe   # 保管庫の領域も消し、新しい初回コードを表示する
```

書き込むと、すべてのアプリがログアウトします。アクセストークンに署名する鍵を、起動のたびに作り直すためです。

## 使い始める

1. 基板を挿します。
2. その機器で、基板の証明書を信頼させます。`https://192.168.237.1/` を開いて鍵を外し、「証明書をダウンロード」で取ります（機器ごとの手順は [docs/SETUP.md](docs/SETUP.md)）。
3. 拡張機能やアプリで「自己ホスト」を選び、サーバのURLを `https://192.168.237.1` にします。
4. 1台でアカウントを作ります。LEDが点滅したらBOOTを押します。他の機器ではログインします（ここでもBOOTを押します）。**ユーザー名はでたらめに選び**（`@` が1つあればよく、本物のアドレスでなくてかまいません）、マスターパスワードと一緒に紙に控えてください。基板はユーザー名を保存しないので、盗まれた基板はずっと解きにくくなります。その代わり、忘れたら誰にも分かりません。
5. 管理ページの「鍵を作る計算を変える」で、Argon2idに変えます。公式のアプリはアカウントを必ずPBKDF2で作り、基板はマスターパスワードを知らないので、自分で変える必要があります。変えるとすべてのアプリがログアウトするので、他の機器でのログインはそのあとにします。
6. 保管庫のタイムアウト時の動作を「ロック」にします。アプリは保管庫の暗号化された写しを手元に持つので、普段の使い方（見る、自動入力、ロックの解除）は基板がなくてもできます。基板が要るのは、ログインと同期のときです。

保管庫をまとめるページ: `https://192.168.237.1/merge` で、2つの保管庫（パスワード付きのエクスポート、tinywardenの控え、この基板そのもの）をブラウザの中で左右に並べて比べ、全部をまとめたもの（空のアカウント用）か、片方に足りない分だけ（そのままインポートする用）を保存できます。

管理ページ: `https://192.168.237.1/` 。いつも鍵付きです。アカウントのユーザー名とマスターパスワードで外します（BOOT。間違いは消去までの回数に数えます）。アカウントを作る前は初回コードで外します。外すと、項目の数、空き容量、最近のリクエストと変更、つないできたアプリとバージョン、鍵を作る計算（KDF）とArgon2idへの切り替え、暗号化した控え、消去、このマニュアル（`/manual`）が見られます。

## 控えと、データの取り出し

アプリは公式のもので、自動で更新されます。いつか更新のせいでtinywardenにログインできなくなっても、データに手が届くように、次の方法を用意しています。

- **管理ページ >「控えを保存」**: ユーザー名、マスターパスワード、BOOTボタン（PBKDF2でもArgon2idでも、ブラウザの中で計算します）。保管庫を暗号化したままダウンロードします。マスターパスワードを間違えると、ログインと同じく、消去までの回数に数えます。ファイルにはユーザー名を入れないので、開くときに聞かれます。
- **`tools/tw_backup.py`** （Pythonの標準ライブラリだけで動きます。Argon2idのアカウントでは `pip install argon2-cffi` も要ります）:
  ```sh
  python3 -I tools/tw_backup.py fetch backup.json            # ログインして（BOOT）、保管庫を暗号化したまま保存する
  python3 -I tools/tw_backup.py decrypt backup.json out.json # オフライン: マスターパスワード → パスワード付きのBitwardenエクスポート
  ```
  `decrypt` は、Bitwardenのパスワード付きJSONエクスポートを書き出します（ファイルのパスワードを聞きます）。これは、BitwardenやVaultwardenの新しいアカウントにインポートできます。`--plain` を付けると、暗号化していないエクスポートを書き出します。エクスポートの形は公式アプリのソースに合わせていますが、本物のBitwardenへのインポートはまだ確かめていません。

戻すときは、移った先（新しいtinywarden、Bitwarden、Vaultwarden）で新しくアカウントを作ってから、インポートします。

## 安全性の考え方

保管庫を守っているのは、**マスターパスワードの強さと、誰も知らないユーザー名**です。パスワードは長くしてください（でたらめな単語を5個以上、またはでたらめな文字を16文字以上）。ユーザー名もでたらめに選び、鍵を作る計算をArgon2idに変えてください。特に次の点に注意してください。

- **基板は封じていません。** フラッシュの暗号化、セキュアブート、ダウンロードモードの無効化は、かけていません（eFuseを焼くので、元に戻せないためです）。基板を手にした人は、フラッシュを読み出せます。
- **読み出して分かること:** KDFの設定と包んだ鍵、記録のおおよその数と大きさ、書き込んだ回数。ユーザー名（保存していません）、項目の中身・種類・数・日時（ログインしたあとにだけメモリにある鍵で暗号化しています）は分かりません。手元でパスワードを試すには、ユーザー名とマスターパスワードを組で当てる必要があります。
- **隠せないこと:** 読み出したものは公開しているファームと一致するので、何の基板かは分かります。BitwardenのAPIのURLは誰にでも答えます（アプリが使うため）。USBの製造元はEspressifと出ます。ファームまで隠せるのは、ハードウェアのフラッシュ暗号化だけです。
- **ログインしたまま挿してある基板を取られたら**、保存用の鍵はメモリにあります。JTAGを閉じていないので、読まれるおそれがあります。
- ログインしたすべての機器も、同じ暗号文の写しを持っています。
- BOOTボタンは、ログイン、アカウントの作成、管理ページの鍵を外すとき、控えの保存、消去のときの2つ目の確認です。マスターパスワードを10回間違えると、保管庫を消去します。
- アクセストークンは、起動ごとに作る鍵で署名します。基板を抜いて挿し直すと、次の同期のときにすべてのアプリがログアウトします。
- アカウントを取り戻す方法はありません。マスターパスワードかユーザー名を忘れたら、保管庫はなくなります。
- 管理ページは、アカウント（アカウントを作る前は初回コード）で鍵を外すまで、機器の情報しか出しません。何の機器か分かるページ・スクリプト・マニュアルは、外す前は「無い」（404）と答えます。

## テスト

```sh
# 保管庫の保存領域を、模擬のNORフラッシュで、任意のバイトで電源を切りながらテストする
cd test/host
cc -std=c11 -O2 -g -Wall -Wextra -fsanitize=address,undefined -I../../firmware/main ../../firmware/main/logstore.c test_logstore.c -o t
ASAN_OPTIONS=detect_leaks=0 ./t

# 控えのツールの暗号（AESをopensslとFIPS-197で確かめる、合成した保管庫）
python3 -I test/host/test_tw_backup.py

# 初回コードの区画の中身（ファームが読む形）
python3 -I test/host/test_setup_code.py

# ブラウザ用の暗号（PBKDF2、Argon2idをRFC 9106とOpenSSLで確かめる、エクスポート）と、マージのページの処理
node test/web/test_twcrypto.mjs
node test/web/test_merge.mjs
```

コミットする前に、一度 `tools/install-hooks.sh` を動かしてください。コミットのたびに、鍵やトークン、手元のフォルダの場所、メールアドレスが入っていないかを確かめます（`tools/check-leaks.sh`）。版の出し方: [release/PUBLISH.md](release/PUBLISH.md)。

`test/device/device_test.py` は、開発用のビルドをAPI越しに動かします。[docs/TESTING.md](docs/TESTING.md) を見てください。

開発用のビルド（`firmware/sdkconfig` の `CONFIG_TW_DEV_DOWNLOAD_ENDPOINT`、`CONFIG_TW_DEV_SKIP_BUTTON`）は、ボタンを飛ばし、テスト用の口を足します。本物の保管庫が入った基板には、絶対に使わないでください。

## 自動でやってはいけないこと

eFuseに書き込む操作すべて（`espefuse.py burn_*`、セキュアブート、フラッシュの暗号化、ダウンロードモードの無効化）。元に戻せません。
