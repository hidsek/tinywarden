# tinywarden 機器ごとの導入

English: [SETUP.en.md](SETUP.en.md)

ふだんの使い方とバックアップは [MANUAL.md](MANUAL.md)、理由や調べた結果は [DECISIONS.md](DECISIONS.md) の「ほかの機器で使えるか」。

## 動くのを確かめた機器（2026-11-19）

| 機器 | 使うもの | 結果 | 気をつけること |
|---|---|---|---|
| Mac | ブラウザの拡張機能（Chrome、Brave） | 使える | — |
| Windows 11 | ブラウザの拡張機能（Chrome、Edge） | 使える | 証明書はコマンドで入れる（ダブルクリックでは通らなかった） |
| iPhone 17（USB-C、iOS 26.5.1） | BitwardenのiOSアプリ | 使える | 証明書を入れたあと「証明書信頼設定」でオンにする |
| moto g24（Android 14） | BitwardenのAndroidアプリ | 使える | 機器と通信するときは、Wi-Fiとモバイル通信を切る |
| Chromebook | ブラウザの拡張機能（Chrome） | 使える（2026-11-24） | 証明書のダウンロードが止められたら保存する。読み込みは `chrome://certificate-manager`。Androidのアプリは試していない |
| Redmi 2201117TL（Android 13） | — | 使えない | 機器がネットワークとして見えない |
| Windows 10 | — | 試していない | 標準のドライバが無いので、使えない見込み |
| Firefox | — | まだ | 許可リストに入っていない（今後の課題） |

どの機器でも、機器は `192.168.237.1`、つないだ側は `192.168.237.2` になる。機器はルーターやDNSを配らないので、つないだ側のインターネットは止まらない。

## 全部の機器に共通

1. **最初のアカウントは、どれか1台で作る。** 2台目からは、同じユーザー名（メール）とマスターパスワードでログインするだけ。ユーザー名は機器に保存されないので、でたらめに選んで紙に控える（[MANUAL.md](MANUAL.md)「ユーザー名の選び方」）
2. **機器ごとに、証明書を1回だけ信頼させる。** 証明書は機器の中で作られ、`http://192.168.237.1/ca.crt` から取れる。名前は `Local CA 192.168.237.1`。管理ページ（`https://192.168.237.1/`）の「証明書 SHA-256」（鍵が掛かっていても出る）と、入れたものが同じかを見ておくと安心。v0.2までの証明書（`tinywarden CA 192.168.237.1`）が入っていたら消す
3. **サーバーのURLは `https://192.168.237.1`。** 拡張機能もアプリも、ログイン画面で「セルフホスト」を選んで入れる
4. **アカウントの作成とログインでは、BOOTボタンを押す。** 基板のLED（GPIO48）が光っているあいだ（30秒以内）に押す。色は基板によって違う
5. **アカウントを作ったら、管理ページで鍵を作る計算をArgon2idに変える。** 管理ページは、作ったユーザー名とマスターパスワードで鍵を外す（アカウントを作る前は、書き込んだときの初回コード）。 アプリは必ずPBKDF2で作るので、作った直後に1回だけ（手順は [MANUAL.md](MANUAL.md) の「鍵を作る計算を変える」）。変えるとログアウトするので、2台目からのログインはそのあとにする
6. **タイムアウトの動作は「ロック」にする。** 「ログアウト」だと、毎回機器とボタンが要る
7. 機器を挿し直して同期すると、ログアウトされる（機器は起動ごとに署名の鍵を作り直すため）。ログインし直せばよい

証明書が作り直されたとき（ファームウェアの更新で証明書の形が変わったとき。まれ）は、どの機器でも古い証明書を消して、新しいものを入れ直す。

## Mac

1. 機器を挿す。「システム設定 → ネットワーク」に「Espressif Device」が出て、`192.168.237.2` をもらう
2. 証明書を信頼させる（macOSのパスワードを聞かれる）
   ```sh
   curl -o ca.crt http://192.168.237.1/ca.crt
   security add-trusted-cert -r trustRoot -p ssl -k ~/Library/Keychains/login.keychain-db ca.crt
   ```
3. ブラウザを一度終了して開き直す
4. 拡張機能でサーバーのURLを `https://192.168.237.1` にして、アカウントを作るかログインする（BOOTボタン）

確かめ方: `curl https://192.168.237.1/alive` が警告なしに答える。

## Windows 11

1. 機器を挿す。ドライバは自動で付く。デバイスマネージャーの「ネットワーク アダプター」に「UsbNcm Host Device」が出る
   - もし「ほかのデバイス」に「！」付きで出たら: 右クリック →「ドライバーの更新」→「コンピューターを参照してドライバーを検索」→「コンピューター上の利用可能なドライバーの一覧から選択します」→「ネットワーク アダプター」→ 製造元「Microsoft」→「UsbNcm Host Device」
2. ブラウザで `http://192.168.237.1/ca.crt` を開いてダウンロードする
3. コマンドプロンプトで証明書を入れる（管理者の権限は要らない。確認が出たら「はい」）
   ```
   certutil -addstore -user Root %USERPROFILE%\Downloads\ca.crt
   ```
   **ダブルクリックで入れる方法では通らなかった**（ウィザードが「信頼されたルート証明機関」以外に入れることがあるため）
4. ChromeかEdgeを一度終了して開き直し、`https://192.168.237.1/` が警告なしに開くかを見る
5. 拡張機能でサーバーのURLを `https://192.168.237.1` にして、ログインする（BOOTボタン）

確かめ方: コマンドプロンプトで `ipconfig` を実行し、`192.168.237.2` があればつながっている。

## Chromebook

1. 機器を挿す。Chromeで `http://192.168.237.1/progress` が開けば、つながっている（設定の画面にアドレスが出ないことがあるが、気にしなくてよい）
2. Chromeで `http://192.168.237.1/ca.crt` を開いてダウンロードする。**「安全でない」として止められたら、`Ctrl + J` のダウンロードの一覧で「保存」を押す**（証明書だけは、まだ信頼させていないのでHTTPで配っているため）
3. アドレス欄に `chrome://certificate-manager` と入れて開き、「ローカル証明書」→「カスタム」→「インポート」で `ca.crt` を選ぶ（設定のメニューからは見つからない版がある。古い版なら `chrome://settings/certificates` の「認証局」）
4. Chromeを全部閉じて開き直し、`https://192.168.237.1/` が警告なしに開くかを見る
5. 拡張機能でサーバーのURLを `https://192.168.237.1` にして、ログインする（BOOTボタン）

## iPhone

USB-CのiPhoneで、ケーブル1本でつなぐ。

1. Macで取った `ca.crt` を、AirDropでiPhoneに送る（Macが無ければ、機器を挿してSafariで `http://192.168.237.1/ca.crt` を開いてもよい）
2. 「設定」の上のほうに出る「ダウンロード済みのプロファイル」を開いて入れる（名前は `Local CA 192.168.237.1`）
3. **「設定 → 一般 → 情報 → 証明書信頼設定」で、`Local CA 192.168.237.1` をオンにする**（これを忘れると「このサーバの証明書は無効です」になる）
4. 機器をiPhoneに挿す。「設定」に「Ethernet」が出る。インターネットはモバイル通信やWi-Fiのまま使える
5. BitwardenのiOSアプリで、ログイン先を「セルフホスト」にし、サーバーのURLに `https://192.168.237.1` を入れて保存する
6. アカウントを作るかログインする（BOOTボタン）

確かめ方: Safariで `https://192.168.237.1/` が警告なしに開く。

## Android

**機種しだい。** USBの有線LANを扱えない機種がある（Redmi 2201117TLはだめだった）。Android 14以降のほうが見込みが高い。

1. 機器をスマホに挿す
2. **機内モードにして、Wi-Fiも切る**（下の「Androidの注意」）
3. Chromeで `http://192.168.237.1/progress` を開く。英語の文字が出れば、つながっている。「インターネットをオンに」と出るなら、その機種では使えない
4. Chromeで `http://192.168.237.1/ca.crt` を開いて、証明書をダウンロードする
5. 「設定 → セキュリティとプライバシー → その他のセキュリティ設定 → 暗号化と認証情報 → 証明書のインストール → CA証明書」で入れる（メニューの名前は機種で少し違う）
6. BitwardenのAndroidアプリで、ログイン先を「セルフホスト」にし、サーバーのURLに `https://192.168.237.1` を入れる
7. ログインする（BOOTボタン）
8. 終わったら、機内モードを切り、機器を抜く

**Androidの注意:** Androidは、アプリの通信を「メインのネットワーク」1つにだけ流す。Wi-Fiやモバイル通信がつながっていると、そちらがメインになり、機器あての通信もそちらに出て行ってタイムアウトする。だから、機器と通信するとき（ログイン、同期）だけ、Wi-Fiとモバイル通信を切る。ふだん見る・自動入力する・ロックを解除するだけなら、アプリの中に保管庫があるので、機器も切り替えも要らない。

ふだんの同期の流れ: 機内モード（Wi-Fiも切る）→ 機器を挿して、アプリで同期 → 機内モードを切る → 機器を抜く（挿したままでもインターネットは戻るが、機器はスマホの電池から電気を取る）。

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| ネットワークが出てこない | 別のケーブルで試す（充電だけのケーブルがある）。Androidは機種しだい |
| 証明書のエラー | その機器で証明書を信頼させたか。iPhoneは「証明書信頼設定」のオン。Windowsは `certutil` で入れたか。ブラウザを開き直したか |
| ログインで「Press the button…」 | 基板のLEDが光っているあいだにBOOTを押す |
| Androidでタイムアウト | Wi-Fiとモバイル通信を切ったか |
| アプリやブラウザで、急にログインできなくなった | アプリの更新で送り方が変わったかもしれない。管理ページの「つないできたアプリ」で版と失敗を見る。中身は管理ページの「控えを保存」で取り出せる（鍵を外してから。MANUAL「バックアップ」） |
