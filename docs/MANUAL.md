# tinywarden の使い方

English: [MANUAL.en.md](MANUAL.en.md)

USBに挿したESP32-S3を、Bitwardenのサーバーにする（ブラウザの拡張機能、iPhone・Androidのアプリ）。**機器ごとの導入は [SETUP.md](SETUP.md)。** 仕組みは `docs/SPEC.md`、検討の経緯は `docs/DECISIONS.md`。

## はじめに知っておくこと

- **マスターパスワードを忘れたら、誰にも戻せない。** 機器にも作者にも、本家のBitwardenにも戻す手段は無い。紙に書いて、大事な書類と一緒にしまっておくのがおすすめ
- **機器を挿し直すと、ログアウトする。** 抜いているあいだは、端末の中の保管庫でそのまま使える。挿し直して同期した時点でログアウトされるので、もう一度ログインする（BOOTボタンが要る）。ファームウェアを書き込んだときも同じ
- **機器が壊れたり、なくなったりすると、保管庫も無くなる。** バックアップを別の場所に持つ（下の「バックアップ」）
- **拡張機能やアプリの更新で、ある日ログインできなくなることがある。** 公式のアプリは自動で更新され、tinywardenが追いつくまで使えないことがありうる。そうなっても中身を取り出せるように、**月に1回は管理ページの「控えを保存」で控えを取っておく**。控えは `tools/tw_backup.py decrypt` で、アプリなしでBitwardenの形に戻せる（下の「例1b」）
- 機器を手に入れた人は、中の暗号文を読み出せる。マスターパスワードが無ければ中身は読めないが、手元で総当たりはできる。**マスターパスワードは長くする**（ランダムな単語4〜5個か、ランダムな16文字以上）
- **ユーザー名（メールアドレス）は、機器に保存されない。** 盗んだ人は、ユーザー名とマスターパスワードを組で当てるしかない。なので、ユーザー名もふつうのメールアドレスではなく、**でたらめに選ぶ**と強くなる（下の「ユーザー名の選び方」）。その代わり、**ユーザー名を忘れると、自分でも開けない**。マスターパスワードと一緒に紙に書いておく

### ユーザー名の選び方

- `@` が1つあればよい。本物のメールアドレスである必要はない（確認のメールは送らない）
- **でたらめな単語を1〜2個**使う（例: `kumo-hashi@home` の形で、単語はサイコロなどで選ぶ）。単語1個で、総当たりの手間が約7776倍になる
- 名前（`tanaka@home`）、短すぎるもの（`a@z`）は、真っ先に試されるのでほとんど効かない
- 機器を複数持つなら、`…@home` と `…@work` のように分けると、拡張機能のアカウントの切り替えで使い分けられる

## 最初の設定

機器ごとの手順（Mac、Windows、iPhone、Android）と、動くのを確かめた機器の一覧は **[SETUP.md](SETUP.md)** にまとめた。流れはどれも同じ:

0. ファームウェアを書き込むと、**初回コード**（`ABCD-EFGH-JKLM` の形）が出る。アカウントを作るまで、管理ページはこのコードで開ける。控えておく
1. 機器を挿す（`192.168.237.2` をもらう。インターネットは止まらない）
2. その機器で、証明書 `Local CA 192.168.237.1` を1回だけ信頼させる
3. 拡張機能かアプリで「セルフホスト」を選び、サーバーのURLに `https://192.168.237.1` を入れる
4. 最初の1台でアカウントを作る（ユーザー名は上の「ユーザー名の選び方」）。**基板のLED（GPIO48）が光っているあいだ（30秒以内）にBOOTボタンを押す**。2台目からはログインだけ（ここでもBOOT）。アカウントを作ると、初回コードは使えなくなる
5. **管理ページで、鍵を作る計算をArgon2idに変える**（下の「鍵を作る計算を変える」）。管理ページは、今作ったユーザー名とマスターパスワードで開ける。アプリはアカウントを作るとき必ずPBKDF2にするので、作った直後に1回だけやる。変えるとログアウトするので、他の機器のログインはこのあとにする
6. 保管庫のタイムアウト時の動作を**「ロック」**にしておく（「ログアウト」だと、毎回機器とボタンが要る）

## ふだんの使い方

**拡張機能もアプリも、保管庫を暗号化したまま端末の中に持っている。** だから、機器を抜いても、アプリを閉じても、スマホを再起動しても、中身は消えない。ロックを解除すれば（マスターパスワード、PINや指紋）、機器なしで見る・自動入力ができる。機器が要るのは、ログインと同期（項目を足す・直す・消すのを機器に反映する）のときだけ。

- 端末の中身が消えるのは: 自分でログアウトしたとき、タイムアウトの動作が「ログアウト」のとき、**機器を挿し直して同期したとき**（機器は起動ごとに署名の鍵を作り直すので、前のトークンを拒み、アプリはログアウトする。ログインし直せば中身は入り直る）
- だから、タイムアウトの動作は「ロック」にしておく
- ロックの解除は、**PINと「ブラウザの再起動時にマスターパスワードでロック」（オン）**の組み合わせがおすすめ。普段はPINで開き、マスターパスワードはブラウザを再起動したあとだけ打つ
  - PINは、その端末のそのアプリの中の写しを開くためだけのもの。ばれても、その端末に触れられなければ使えない。マスターパスワードがばれると、暗号文を持つ人（ログインした端末、基板、控え）には全部読まれる
  - 「再起動時にマスターパスワードでロック」をオフにすると、PINで開く鍵がディスクに残る。ファイルを盗まれると、短いPINは手元で総当たりされる。なのでオンにしておく
  - PINを盗み見られたかもと思ったら、その端末でPINを変える。ほかの端末とマスターパスワードはそのままでいい

- ふだんは拡張機能だけで使う。ロックの解除は拡張機能の中で済むので、ボタンは要らない
- ボタンが要るのは、アカウントの作成、パスワードでのログイン（新しいブラウザ、抜き挿しのあと）、管理ページの鍵を外すとき、管理ページからの控えの保存・鍵の計算の変更・全消去だけ
- 基板のLED（GPIO48）が光るのは、ボタン待ちのしるし。色は基板によって違う（SuperMiniでは赤っぽく見えるものがある）。光っているあいだ、機器はほかの通信に答えない
- 基板の「BAT」の青いLEDが点滅し続けるのは、充電回路が電池を探しているだけで、故障ではない。ファームウェアからは消せないので、気になるならテープでふさぐか、ケースに入れる

## 管理ページ

ブラウザで `https://192.168.237.1/` を開く。**いつも鍵が掛かっている。** 鍵が掛かっているあいだは、機器の情報（チップ、版、起動からの時間、メモリ）しか出ない。証明書は、鍵を外したページから取る。USBにつないだだけの人には、何の機器か分からない。

- **鍵を外す:** ユーザー名とマスターパスワードを入れて「解除」を押し、基板のLEDが光っているあいだにBOOTを押す。マスターパスワードはページの中でハッシュにしてから送るので、機器には届かない。**間違いはログインの失敗と同じく数え、10回続けて間違えると全部消える**
- アカウントを作る前は、ユーザー名とパスワードの代わりに**初回コード**を入れる（書き込んだときに出たもの。ハイフンや大文字小文字は気にしなくてよい）
- 外した鍵は30分で自動で掛かる。「鍵を掛ける」ですぐ掛けられる。機器を挿し直しても掛かる
- 鍵を外すと、**使い方（このマニュアル）**も機器の中で読める（`https://192.168.237.1/manual`）

| 見るところ | 分かること |
|---|---|
| 項目・フォルダ | 件数（鍵を外したときに数える） |
| 保存領域・あと入る件数 | 空き。1件平均2.6KBとして、約1,000件入る |
| 古い版 | 編集や削除で残った古い版の量。いっぱいになる前に、機器が自分で片付ける |
| 起動時の読み込み | 赤字が出たら、書き込み中に電源が切れた跡（書きかけの1件を捨てた） |
| 直近の通信 | うまくいかないとき、どこで止まったかが分かる |
| 最近の変更 | いつ、何が保存・削除されたか（中身は暗号文なので、項目の名前は出ない。削除したものは種類も出ない） |

機器の中は、ユーザー名を除いて全部、暗号化して保存している（項目の種類・数・日時も）。鍵は、誰かがログインしたときにだけ機器のメモリに入り、挿し直すと消える。

## インポート

1. 今使っているサービスからエクスポートする。おすすめは**パスワード付きJSON（「ファイルのパスワード」の種類）**。「アカウント制限」の種類は、tinywardenの新しいアカウントには入らない
2. 拡張機能の「設定 → 保管庫のオプション → インポート」で、そのファイルを選ぶ
3. 約800件で15秒くらい。進み具合は `http://192.168.237.1/progress` で見られる（インポート中、管理ページは開けない）

| 形式          | 入るもの                             |
| ----------- | -------------------------------- |
| パスワード付きJSON | 全部（フォルダ、カード、個人情報、パスキー）           |
| JSON        | 全部。ただしファイルが暗号化されていないので、終わったらすぐ消す |
| CSV         | ログインとセキュアメモだけ                    |

どの形式でも、添付ファイルは入らない。

- **2回インポートすると、項目が2つずつになる**（Bitwardenは重複を確かめない）
- 入りきらないときは、1件も入れずに「空きが足りない」と出る。途中まで入ることはない（電源が切れた場合を除く）
- 1回に送れるのは約1.7MB（約1,000件）まで。超えると「大きすぎる」と出る

## 保管庫をまとめる（`https://192.168.237.1/merge`）

2つの保管庫を見比べて、1つにまとめるか、足りない分だけを書き出す。管理ページの「保管庫をまとめる」から開く。計算はすべてブラウザの中で行い、中身は基板にもネットにも送らない（ページを閉じれば消える）。

- **入れ方:** AとBのそれぞれで、まず「ファイル」か「この基板」かを選ぶ。ファイルなら、選んだファイルの種類に合わせて、ファイルのパスワードか、そのアカウントのユーザー名とマスターパスワードの欄だけが出る（v0.2までの控えはユーザー名が控えに入っているので、聞かない）。この基板なら、ユーザー名とマスターパスワード。AとBは別々のアカウントでもよい
- **入れられるもの（AとBに1つずつ）:** パスワード付きのエクスポート（VaultwardenやBitwardenで「パスワード付き」を選んで取ったもの）、tinywardenの控え、暗号化していないエクスポート、この基板の今の中身（ユーザー名・マスターパスワード・BOOT）。Bitwarden・Vaultwardenの「アカウント制限付き」エクスポートは、鍵がサーバーにあるので開けない（エクスポートし直すときに「パスワード付き」を選ぶ）。使うパスワードは、パスワード付きのエクスポートならエクスポートしたときに決めたファイルのパスワード、tinywardenの控えならマスターパスワード（ページにも出る）
- **比べ方:** 同じIDなら同じ項目。インポートでIDが変わったものは、種類・名前・ユーザー名・URLのホスト名で合わせる。空の書き方の違い（空文字と欄なしなど）、パスキーを使った回数、パスワードの更新日は、違いに数えない
- **画面:** 左にA、右にBのカードを並べ、違う欄に色を付ける。上に「差分なし」か、違う・Aだけ・Bだけの件数と、保存したときの件数を出す。残す方のカードを押して選ぶ（緑の枠）。真ん中で「両方」「捨てる」。初めは、違うものは更新日が新しい方、片方だけのものは残す。パスワードなどは伏せてあり、「隠した値を見せる」で見られる
- **保存:** 「全部まとめる」と「足りない分だけ」（Aに入れるかBに入れるか、それぞれの追加と手で消す件数つき）を左右に並べてあり、選んでから、ファイルのパスワードと鍵の作り方を決めて保存する
- **保存のしかた（どれもパスワード付きのエクスポート）:** ファイルの鍵の作り方は、初めはArgon2id。インポートでファイルを開くのはアプリなので、相手がBitwardenのクラウドでもVaultwardenでも読める（今の公式アプリはArgon2idのファイルに対応している）。古いアプリやBitwarden以外のツールで読むときは、PBKDF2を選ぶ
  - **全部まとめて保存:** 選んだとおりの全体。**空のアカウント**にインポートする（中身があるところに入れると二重になる）
  - **Bに足りない分だけ保存／Aに足りない分だけ保存:** 相手にない項目と、違う項目のうち相手でない方を選んだもの。**今のアカウントにそのままインポート**できる。インポートは追加しかできないので、相手側に残る古い方と、「捨てる」を選んだ相手側の項目は、画面に出る一覧を見て手で消す
- **使い方の例:**
  - クラウドで足した分だけをtinywardenに入れる: A＝この基板、B＝クラウドのエクスポート →「Aに足りない分だけ保存」→ tinywardenにインポート
  - tinywardenの控えをインポートできる形にする（ターミナルなし）: Aに控えだけを入れて「全部まとめて保存」
- AとBでパスワードが違う項目は、選ばなかった方のパスワードを、残した項目の「パスワードの履歴」に入れておく（新しい順に5つまで）。間違えて選んでも、古いパスワードを確かめられる
- フォルダは名前で合わせる。インポートしたときに、同じ名前のフォルダが二重にできるかは未確認

## 鍵を作る計算を変える（Argon2id）

マスターパスワードから保管庫の鍵を作る計算（KDF）を、PBKDF2からArgon2idに変える。

- **なぜ変えるか:** 暗号文を盗まれたとき（基板、ログインした端末の写し、控え）、相手はマスターパスワードを1つずつ試す。Argon2idは1回ごとに大きなメモリ（32MB）が要るので、GPUを並べても試す速さが上がりにくい（PBKDF2の20分の1くらい、という見積もり）。いちばん効くのはマスターパスワードを長くすることで、Argon2idはその上の保険
- **なぜ自分で変えるのか:** 公式のアプリは、アカウントを作るとき必ずPBKDF2（60万回）にする。基板はマスターパスワードを知らないので、あとから勝手には変えられない。VaultwardenやBitwardenのクラウドでも、自分でWeb保管庫の設定から変える
- **やり方:**
  1. 「控えを保存」で控えを取っておく
  2. 管理ページの「鍵を作る計算を変える」で、ユーザー名とマスターパスワードを入れ、「Argon2id（メモリ32MB、6回、並列4）」のまま「変える」を押す
  3. 基板のLEDが光ったらBOOTを押す。そこから2分以内に、ページが新しい鍵の包み方を作って送る（Argon2idの計算でパソコンなら数秒）
  4. 「変えました」と出て、表の「鍵を作る計算（KDF）」がArgon2idになれば終わり
- **変えたあと:** すべての機器がログアウトする。拡張機能もスマホのアプリも、ログインし直す（BOOT）。保管庫の中身はそのまま（包み直すのは保管庫の鍵だけ）
- 値はBitwardenのアプリがArgon2idを選んだときの初期値。iPhoneの自動入力の画面は使えるメモリが小さいので、メモリは増やさない
- Face IDや指紋でロックを解除するときは、端末にしまった鍵を出すだけなので、計算は起きない。マスターパスワードやPINで解除するときに、Argon2idの計算をする（スマホで1〜2秒）
- PBKDF2に戻すこともできる（同じ欄で「PBKDF2（60万回）」を選ぶ）

## 全部消す

管理ページの鍵を外し、一番下で「消去」と入力し、「全部消す」を押して、基板のLEDが光っているあいだにBOOTボタンを押す。アカウントも項目も全部消える。証明書は残るので、Macの設定はそのままでよい。

マスターパスワードを10回続けて間違えたときも（ログインでも、管理ページの鍵でも）、同じように全部消える。

- 消したあとは、拡張機能やアプリからアカウントを作り直せる。ただし初回コードは、最初にアカウントを作ったときに消えている。作り直す前に管理ページ（とマニュアル）を開きたいなら、ファームウェアを書き込み直して、新しい初回コードをもらう（書き込みのページなら「Erase device」なしでも新しいコードが入る）
- ユーザー名やマスターパスワードを忘れて管理ページを開けないときは、書き込みのページで「Erase device」にチェックして書き込み直す（全部消える）

## バックアップ

機器が壊れたり、なくなったりしても困らないように、暗号化した控えを別の場所に持っておく。**どうするかは自由。** 以下は一例。

### 例1: 月に1回、パスワード付きJSONを保存する

1. 拡張機能から、パスワード付きJSON（「ファイルのパスワード」の種類）でエクスポートする
2. そのファイルを、機器とは別の場所に置く（クラウドのストレージ、暗号化したUSBメモリなど）
3. 古い控えも何世代か残しておく（先月、先々月…）。壊れた中身をそのまま控えてしまっても、前の世代に戻れる

- ファイルのパスワードは、マスターパスワードと同じくらい長くする。ファイルを取られると、手元で総当たりされる
- 平文のJSONやCSVは、クラウドに置かない

### 例1b: アプリを使わずに控えを取る（管理ページ、`tools/tw_backup.py`）

拡張機能やアプリの更新で、ある日ログインできなくなっても中身を取り出せるようにするための方法。

**管理ページから**（いちばん手軽。Macでも iPhoneでも）: 管理ページの「控えを保存」で、ユーザー名とマスターパスワードを入れて押し、基板のLEDが光っているあいだにBOOTを押す。マスターパスワードはページの中でハッシュにしてから送るので、機器には届かない。間違いはログインの失敗と同じく数えられ、10回で全部消える。`backup-日付.json` が保存される。中身は暗号化されたまま。**控えにはユーザー名を入れない**ので、開くとき（`decrypt`、まとめるページ）にユーザー名も入れる。

**Macのコマンドで**:

拡張機能やアプリの更新で、ある日ログインできなくなっても中身を取り出せるようにするための道具。MacのPythonだけで動き、何も入れなくてよい。

```sh
python3 -I tools/tw_backup.py fetch backup.json            # ログインして（BOOTを押す）、暗号化されたまま保存
python3 -I tools/tw_backup.py decrypt backup.json out.json # マスターパスワードで解き、パスワード付きのBitwardenのエクスポートにする（機器は要らない）
```

- 管理ページで保存したファイルも、`decrypt` でそのまま戻せる。ユーザー名を聞かれる（v0.2までの控えは、ユーザー名が入っているので聞かない）
- `fetch` で保存したファイルは暗号化されたままなので、パスワード付きJSONと同じように扱える。保存したときに、そのマスターパスワードで解けることも確かめる
- `decrypt` は、新しいファイルのパスワード（12文字以上）を聞き、Bitwardenの「パスワード付きのエクスポート」と同じ形で `out.json` を書く。暗号化されていないファイルはディスクに残らない。インポートのときにそのパスワードを入れる
- `--plain` を付けると暗号化されていないJSONを書く。使うのは、パスワード付きを読めない移る先だけにして、インポートしたらすぐ消す
- ゴミ箱の項目は含めない。添付ファイルには対応していない（tinywardenが添付を扱わないため）
- Argon2idのアカウントは、`tools/tw_backup.py` を使うときに `pip install argon2-cffi` が要る（PBKDF2なら要らない）。管理ページの「控えを保存」は、どちらでもブラウザの中で計算する

### 例2: 予備の機器をもう1台用意する

1. 2台目を最初の設定までしておく（証明書も2台目のぶんを信頼させる）。同時には挿さない（どちらも `192.168.237.1` を名乗るので）
2. 月に1回、1台目からエクスポートし、2台目を挿して全消去してからインポートする
3. 2台目の管理ページで、件数が1台目と同じか見る
4. 2台目は、1台目とは別の場所にしまう

1台目が壊れたら、2台目を挿してログインすれば、最後に写した時点の保管庫で使える。「控えが本当に戻せるか」も毎月確かめることになる。

### 戻すとき

**移る先で新しくアカウントを作り、そこにインポートする。** 移る先は、新しいtinywarden（か全消去した機器）、Bitwardenのクラウド、Vaultwardenのどれでもよい。

- パスワード付きJSON（例1）なら、そのままインポートする
- 管理ページや `tw_backup.py` の控え（例1b）なら、先に `python3 -I tools/tw_backup.py decrypt 控え.json out.json` でパスワード付きのエクスポートにしてから、`out.json` をインポートする（ファイルのパスワードを聞かれる）
- 機器の暗号文をそのまま別の機器に書き戻す機能は作らない。新しいアカウントに入れ直すほうが、移る先を選ばず、確実なため

## v0.2からv0.3に移す

v0.3で保存の形が変わった（ユーザー名を保存しない、全部を暗号化する）。**v0.2の保管庫は、v0.3では開けない。** 機器の中で自動では移さないので、次の順に移す。

1. **v0.2のまま**、拡張機能から**パスワード付きJSON**でエクスポートする（「設定 → 保管庫のオプション → エクスポート」、「ファイルのパスワード」の種類）。念のため、管理ページの「控えを保存」でも控えを取る
2. 書き込みのページで、**「Erase device」にチェックして**v0.3を書き込む。**初回コード**を控える
3. 証明書も作り直されている（名前が `Local CA 192.168.237.1` になった）。各端末で、古い `tinywarden CA 192.168.237.1` を消し、新しい証明書を入れる（[SETUP.md](SETUP.md)）
4. 新しいユーザー名（でたらめに選んだもの）とマスターパスワードで、アカウントを作る（BOOT）
5. 管理ページを新しいユーザー名とマスターパスワードで開き、鍵を作る計算をArgon2idに変える
6. 拡張機能でログインし直し、1のファイルをインポートする（ファイルのパスワード）
7. ほかの端末で、新しいユーザー名でログインし直す。件数が合っているか、管理ページで見る

v0.2のまま書き込み直さずにv0.3を入れると、ログインは「古い形式です」と断られる（失敗の回数には数えないので、消えはしない）。

## 長く使うために（基板の寿命と弱いところ）

大事に保管すれば、基板は10年くらいは持つと考えてよい（数字はどれも一般的な目安で、この基板で測ったものではない）。ただし、手放しで何十年も、とはいかない。

| 部分 | 寿命の目安 | 気をつけること |
|---|---|---|
| フラッシュ（保管庫が入るところ） | 一般的なNORフラッシュは、データを20年ほど保てる設計。温度が高いほど短くなる | 書き換えの回数にも上限がある（1か所あたり10万回ほど）。tinywardenは書き込みを全体に分けているので、ふつうの使い方なら問題ない |
| チップそのもの | 何十年も持つのがふつう | 静電気に弱い。触る前に、金属に触れて放電する |
| USBの口 | 抜き挿しで、すり減る | いちばん先に壊れやすい |
| はんだ・基板 | 湿気で錆びる | 湿気の少ない場所に、静電気を防ぐ袋（帯電防止袋）に入れて保管する |
| 安い互換品 | 個体によって品質の差が大きい | 2枚用意しておくと安心 |

**いちばん先に限界が来やすいのは、基板よりも「公式のアプリが更新されて、つながらなくなること」。** だから、しばらく使わないときも、年に1回は挿して確かめる。

### しまっておく、引き継ぐ（もしものとき）

保管庫が物として手元にあるので、家族に引き継ぐこともできる。

- 涼しくて乾いた場所に、帯電防止袋と乾燥剤と一緒にしまう
- 年に1回くらい挿して、開けるか確かめる。そのときに控えも取り直す（「控えを保存」、または「保管庫をまとめる」でインポートできる形にする）
- 基板は2枚にして、片方を予備にする。控えのファイルとマスターパスワードの紙は、基板とは別の場所にも置く
- 引き継ぐ人のために、「挿す → 証明書を信頼させる → 拡張機能でサーバーのURLを入れて、ユーザー名とマスターパスワードでログイン（BOOTを押す）」の手順を紙1枚に書いて、一緒にしておく。ユーザー名は機器に残っていないので、紙に書いておかないと引き継げない。アプリが更新されて使えなくなっていたら、控えをBitwardenなどの新しいアカウントにインポートすれば中身は取り出せる（「戻すとき」）

## うまくいかないとき

| 起きたこと | どうする |
|---|---|
| 機器を挿すとインターネットが止まる | 古いファームウェア（ゲートウェイを配っていた版）。抜けば戻る。新しいファームウェアを書き込む |
| 拡張機能で証明書のエラーが出る | 証明書を信頼させたか確かめる。ブラウザを一度終了して開き直す |
| iPhoneで「このサーバの証明書は無効です」 | 「証明書信頼設定」でオンにしたか確かめる。ファームウェアの更新で証明書が作り直されたときは、古いプロファイルを消して入れ直す |
| ログインできない、作成できない | BOOTボタンを、基板のLEDが光っているあいだに押したか。ユーザー名は合っているか（機器は覚えていないので、違っていてもパスワード違いと同じに見える）。管理ページの「直近の通信」でエラーの文章を見る |
| 「古い形式です」と出る | v0.2の保管庫のまま、v0.3を書き込んだ。上の「v0.2からv0.3に移す」 |
| 管理ページで「コードが違います」 | 書き込んだときの初回コードか。書き込み直すとコードは変わる。アカウントを作ったあとは使えない（ユーザー名とマスターパスワードで開く） |
| ユーザー名を忘れた | 機器からは分からない。ログインしたままの端末があれば、拡張機能やアプリのアカウントの表示に出ている。どこにも無ければ、機器も、管理ページの控えも開けない。パスワード付きのエクスポートは、ファイルのパスワードだけで開けるので、それを新しいアカウントにインポートする |
| 急にログアウトされた | 機器が抜けたか、再起動した（管理ページの「前回の再起動の理由」）。ログインし直す |
| 機器が何も答えない | 基板のRSTボタンを1回押す。だめなら抜いて挿し直す |
| インポートで「大きすぎる」 | エクスポートを2つに分けて、1つずつ入れる |
| インポートで「空きが足りない」 | 管理ページで空きを見る。要らない項目を消すか、インポートするものを減らす |

## ファームウェアを書き込む（開発する人向け）

1. 書き込みモードにする: BOOTを押したまま、RSTを押して離し、1秒待ってBOOTを離す
2. `./flash.sh`（保存の形が変わったときは `./flash.sh --wipe`。保管庫が消え、新しい初回コードが最後に出る）
3. 書き込みのあとは自動で起動する。ログアウトしているので、ログインし直す

`firmware/sdkconfig` で開発用の機能（`CONFIG_TW_DEV_DOWNLOAD_ENDPOINT`、`CONFIG_TW_DEV_SKIP_BUTTON`）を有効にしたビルドは、本物の保管庫に使わない。とくに `CONFIG_TW_DEV_SKIP_BUTTON` はボタンの確認を省くので、誰でもログインや全消去ができてしまう。
